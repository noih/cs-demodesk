# 本場行為評分實作計畫

狀態：已完成共用分析模組、準星吸附診斷、統一計分器、應用程式自動／手動評分及追加式歷史 UI。正式扣分仍被資料資格與獨立校準條件阻擋；目前不將診斷結果呈現為信用分數。資料契約見 [準星吸附](crosshair-lock.md) 與 [analysis-data.md](analysis-data.md)。

## 1. 目標與範圍

- 以單場 demo × 玩家為評分單位，從 100 分依規則扣分。
- 每筆扣分都有原因、測量依據與可定位的片段。
- 新增、停用、移除規則只修改規則檔案及明確註冊清單；計分器與 UI 依統一結果呈現。
- 本場信用評分用來協助判斷玩家是否使用輔助／外掛；使用 0～100 分，不加百分號、不代表作弊機率，也不累積永久信用。100 分代表已完成的檢查沒有扣分，不保證沒有使用外掛。
- 優先避免誤判。嚴重程度決定扣分幅度，證據充分程度決定是否可以扣分；單次薄弱疑點不直接重扣。
- 個別規則資料或樣本不足不扣分；至少一條規則完成且沒有執行失敗，即可產生分數。所有規則都無法完成時顯示「無法評估」；任一規則執行失敗則顯示「評分失敗，可重試」，兩者均不產生新總分。
- 第一版不加入機器學習、跨場信用、動態外掛、規則編輯後台或未驗證的「正常／作弊」分數區間。

## 3. 實作前資料驗證與規則選擇

先完成每條候選規則的資料表：來源欄位、是否真的解碼、單位、有效範圍、取樣頻率、缺失表示、有效樣本定義與可保存證據。

- 驗證玩家識別、回合邊界、同 tick 事件順序、射擊／命中配對及武器正規化。
- 驗證視角環繞、移動、蹲姿、換槍、缺樣與壓槍序列中斷的既有處理是否能重用。
- 平均壓槍軌跡可能抵銷誤差；不得把平均吻合或高命中率直接當成異常證據。
- 現有穿煙或穿牆擊殺旗標不等同玩家不可見目標，也不單獨構成扣分理由。
- 缺少可見性證據時，不啟用反應時間、隔牆追蹤或準星預瞄等依賴可見性的規則。

首批已選定「準星吸附」：檢查準星從未吸附到貼合的軌跡、移動速度／跳轉，以及貼合後對敵人身體固定位置的跟隨誤差與持續時間，不限部位。不計可見後反應時間，不要求射擊、壓槍、目標變向；靜止對準本身不算。單次可以少扣，持續及重複可增加扣分；隔牆、隔煙、致盲加重，同段只取最高情境，遮蔽後延續的吸附也適用。先前提出的兩條壓槍候選未採用。其餘規則尚未選定，不為湊數啟用扣分。

每條規則啟用前，固定門檻、最低有效樣本、扣分政策、規則上限與類別上限，附正常、高技巧、候選異常及資料不足案例。校準資料與驗證資料分離；候選異常不當作已確認作弊標籤。

## 4. 規則契約

預計新增 `crates/demodesk-core/src/scoring/`，以普通函式及明確清單組成：

```text
scoring/
  mod.rs           # 共用契約與評分入口
  calculate.rs     # 去重、扣分、上限與總分
  rules/
    mod.rs         # 明確註冊啟用規則
    <rule>.rs      # 個別檢查函式與規則定義
```

不建立動態載入器、trait 外掛框架或額外設定管理系統。檔案分工以實際首條規則需求為準。

每條規則定義：固定 ID、版本、名稱、說明、類別、必要資料、最低樣本、扣分政策、上限與檢查函式。規則必須使用既有契約輸出，不能要求 UI 加入專屬判斷。

檢查結果分為：

| 狀態 | 意義 |
| --- | --- |
| 未發現異常 | 必要資料與有效樣本達標，未觸發條件。 |
| 發現異常 | 達到評估條件，產生候選異常及證據；最終扣分仍由計分器決定。 |
| 資料不足 | 缺必要資料或未達最低樣本，附具體原因與樣本數。 |
| 執行失敗 | 檢查未完成，保存錯誤原因，不視為通過。 |

必要欄位缺失不能以零、false 或其他猜測值補齊後通過檢查。非法數值、無效 tick rate、缺少身份或片段定位資料都需明確處理。

## 5. 證據、去重與計分

```text
解析資料 → 規則檢查 → 候選異常與證據
         → 去重分組 → 扣分政策與上限 → 最終明細與總分
```

證據至少保存：規則 ID、穩定事件識別、玩家及目標、正規化回合、片段起訖 tick、tick rate、觀察值與單位、門檻、有效樣本數及觸發原因。時間由 tick 換算，不維護第二套時間判斷。

計分順序固定：

1. 驗證候選證據，拒絕無法定位或含非法數值的結果。
2. 依穩定事件鍵移除相同證據；規則宣告去重群組，避免只因時間重疊就合併不相關行為。
3. 同一玩家、回合與去重群組內，依明確交戰鍵或固定時間窗分組。首條規則落地時，必須定義目標是否屬於分組鍵、時間窗邊界與連鎖重疊是否合併，並寫入 ruleset 版本。
4. 同組重複或相關異常只取最高候選扣分；同分以規則 ID、起始 tick、穩定事件鍵決定順序，保留被合併的支持證據。
5. 第一版使用非負整數扣分；需要比例換算時，只在候選扣分形成時統一四捨五入一次。
6. 依候選扣分由大到小、同分沿用上述穩定順序分配實際扣分；每筆同時受規則、類別、跨類別輕微異常合計上限及全場 100 分剩餘額度限制，取其中最小可用額度。將裁減後的實際扣分寫回明細，扣分合計不得超過 100。
7. 只把實際扣分大於零的項目列入扣分清單；零扣分候選仍留在評估結果，附去重或上限原因。
8. 由最終明細計算：`總分 = max(0, 100 − 實際扣分總和)`；前端直接顯示保存值。

不平均分配 100 分給規則。輕微異常合計上限必須低於 100，不能靠大量小疑點扣光分數；每個類別上限也必須低於 100，單一類別的強證據可以重扣但不能單獨扣到 0。具體扣分、輕微異常定義及上限待首批規則驗證後制定。新增規則需檢查是否重複涵蓋既有行為，不能只靠增加相關規則加重處罰。

規則、類別、輕微異常與全場上限、去重參數及固定排序均屬於評分版本的一部分。不得因註冊順序、HashMap 迭代順序或平行執行完成順序改變結果。

## 6. 可評分條件與失敗處理

- 至少一條規則完成檢查，且沒有規則執行失敗：依實際扣分產生分數；沒有扣分時為 100。
- 個別規則缺資料或樣本不足：該規則不扣分，保留原因，不阻止其他已完成規則產生分數。
- 沒有啟用規則，或所有規則都因資料／樣本不足而無法完成：總分為 null，顯示「無法評估」。
- 任一規則執行失敗：本次不產生新總分，顯示「評分失敗，可重試」；記錄失敗原因並保留已有歷史結果，不能把舊分數當成本次成功結果。
- 「完成檢查」不等於「觸發扣分」；檢查完成且未發現異常是有效評估。
- 分數旁不顯示部分／完整評估標示或完整度比例。各規則既有狀態、有效樣本與不足原因仍保留於結果及規則明細。

## 7. 用戶畫面

在單場玩家分析中提供資料驅動的評分區塊，沿用既有 UI 元件與語系資源。

- 本場摘要：0～100 分信用評分、無法評估或評分失敗，附 ruleset 版本；不顯示完整度標示，不將分數呈現為機率。
- 評分規則：本次啟用規則、檢查內容、扣分條件、最高扣分與實際評估狀態。
- 扣分原因：規則名稱、實際扣分、易懂原因、片段、觀察值、門檻與有效樣本。
- 規則明細：保留未評估／失敗原因，不混入通過項目；評分失敗提供重試入口。
- 開啟玩家分析時自動評分並保存；相同來源內容已有結果時直接讀取（包含未評估與失敗，手動重試追加結果）。提供「重新評分」按鈕；規則更新後保留舊結果，由使用者重新評分產生新版，顯示其版本，不靜默替換歷史分數。
- 回放入口：將玩家及起始 tick 傳到既有 2D 回放，處理非同步載入與切換 demo 後失效的定位請求；尚未支援時顯示回合及時間，不提供無效按鈕。

UI 不重算狀態、去重或扣分。歷史規則無法在目前語系找到對應文字時，使用保存的文字快照呈現。

## 8. 保存、版本與歷史結果

沿用 `store.rs` 的純檔案與原子寫入方式，不新增資料庫。評分歷史需與可拋棄的解析快取分開，使用所選資料目錄下的 `scoring/<demo-player-key>/assessment-<id>.json`。

每次評分保存獨立結果，包含：

- demo ID、來源內容指紋與玩家識別；現有 demo ID 是路徑雜湊，不能單獨識別同一路徑被替換的內容。
- 解析器／資料 schema 版本、ruleset 版本、規則版本、實際參數、規則、類別、輕微異常與全場上限及去重政策。
- 當時規則名稱、說明與扣分原因文字快照，及可供語系化的穩定識別與參數。
- 各規則狀態、有效樣本、原始候選證據、合併關係、最終扣分明細、可評分狀態及總分。

規則更新、快取 schema 更新、重新解析不得自動覆寫舊評分。重新評分產生新結果；同輸入及版本的評分內容必須相同，執行識別或建立時間不列入此一致性比較。

清除解析快取仍沿用原有語義，不連帶刪除評分歷史；評分刪除需有明確操作與範圍。來源 demo 不存在或內容不符時保留可讀歷史，停用回放定位，不能跳到另一份 demo。

需同步更新資料儲存文件，說明新增檔案、清除／刪除行為與資料生命週期。真實 demo、玩家識別及校準輸出只放忽略的本機目錄，提交的測試使用合成身份。

## 9. 實作順序與完成條件

| 階段 | 工作 | 完成條件 |
| --- | --- | --- |
| 1. 資料盤點 | 驗證事件、時間、樣本、證據與既有流程；選首條規則 | 列出已驗證欄位、限制、首條規則定義與驗證材料；門檻及分組政策不再留白。 |
| 2. 垂直流程 | 建立最小契約、註冊清單、單條規則與統一計分器 | 核心可產生確定性的狀態、證據、扣分與可空總分。 |
| 3. 保存與 UI | 接上歷史快照、玩家摘要、明細及回放定位 | 畫面可對帳，重啟可讀，規則移除仍可解釋歷史。 |
| 4. 規則擴充 | 加入通過資料與校準驗證的其他規則 | 新增或停用規則不修改計分器與通用 UI；無足夠證據則延後。 |
| 5. 獨立驗證 | 使用未參與校準的正常、高技巧、候選異常及不足案例 | 記錄誤觸發、漏檢與限制，未達條件的規則不啟用。 |

使用者已授權開始實作「準星吸附」。目前已接通核心、Tauri 命令、玩家切換、自動評估、重新評估、歷史選取與診斷明細。片段提供回合及時間定位。真實 demo 的 10 名玩家完成應用引擎整合測試，36,640 筆測量樣本未產生候選觀察；這不是正常／外掛辨識效能證明。未完成項目是正式資料資格、全場測量自動產製與獨立校準，因此準星吸附目前只回傳未評估或執行失敗。

## 10. 測試與驗收

實作時沿用 Rust 內建測試與專案現有 Node 測試工具，不新增測試框架。至少覆蓋：

- 相同輸入／版本產生一致結果；調換候選順序不影響結果。
- 同一交戰重複證據只扣一次，不同回合或不相關群組不誤合併；涵蓋時間窗邊界及同分排序。
- 規則、類別、跨類別輕微異常及全場上限、取整與最終明細對帳；實際扣分合計不得超過 100，輕微異常合計或單一類別均不能扣光分數。
- 缺欄位、零樣本、最低樣本邊界、非法數值及執行失敗不當作通過。
- 至少一條規則完成、其餘樣本不足且無執行失敗時仍產生分數；無扣分為 100。無啟用規則或全部資料不足時顯示無法評估。
- 任一規則執行失敗即不產生新總分，可重試且保留歷史結果；失敗不能被零扣分掩蓋。
- 開啟玩家分析自動評分，已有相同來源內容結果時重用；手動重新評分保存新結果，不覆寫歷史。
- 首批規則的正常、高技巧與觸發邊界；缺樣、換槍或回合切換不跨段拼接。
- 規則停用／移除、新版本重新分析、快取清除與重啟後，歷史證據與實際扣分仍可讀。
- 來源 demo 內容變更時，不將舊評分或回放入口套用到新內容。
- 畫面只顯示實際扣分，回放載入後正確定位；不足及失敗狀態清楚呈現。

依修改範圍執行 `npm run test:core`、`npm run build`；若變更回放、壓槍或 UI 行為，追加 `npm run test:replay`、`npm run test:recoil`、`npm run test:ui` 的相關檢查。提交前以 `npm run test:privacy` 檢查資料洩漏。目前離線核心的針對性命令為 `cargo test -p demodesk-core --lib scoring::crosshair_lock`；核心修改仍需通過既有核心測試。


## 11. 共用分析資料共識

地圖／場景重建獨立於 rules，供多條規則共用。牆面物理、動態實體、煙霧、玩家姿態各自負責資料轉換，以資料契約及窄提供者介面銜接；只有組裝入口決定使用哪個實作。遊戲更新只修改受影響的適配器及其依赖結果，不要求重寫所有規則。

各模組分別保存資料格式版本、實作版本及來源 demo／遊戲／地圖內容識別；規則版本獨立保存。未知版本或無法驗證相容性不能默認為已驗證。舊結果不覆寫，不支援的舊格式明確拒絕。詳細契約、當前實作及限制見 [analysis-data.md](analysis-data.md)。

目前已有離線附件時間對齊、局部幾何驗證與部分命中膠囊重建；來源版本已區分 demo build／patch 與本機安裝欄位。歷史模型內容與伺服器骨骼時間尚未核實，因此資料仍用於診斷，不啟用正式扣分。
