# 異常分析的改版相容性改進計畫

狀態：已實作並以本機已知 demo 驗證；各項尚未取得證據的範圍見本文末。日期：2026-09-27。

本文件記錄改版相容性的設計與驗收依據。沿用現有 Rust 解析器、資源快取、
擷取腳本與測試，不另建外掛平台、資料庫或背景監控服務。

## 目標與不可改變的要求

目標是讓一般資料、資源與設定更新由既有解析路徑處理；真正的運算變更由回歸
檢查指出最小受影響範圍，避免每次從整個遊戲重新研究。

- 舊動畫 v2、目前 v3、舊分析結果的讀取與顯示必須保留。
- 不用猜測的姿勢、設定或插值補出「100%」。無法還原須有可追查的原因。
- 異常列表只呈現有實際紀錄的項目；不顯示資料不足提示、空項目或 0% 穿煙率。
  確認的穿煙命中次數與估算命中率分開；比率為零仍可保留實際命中紀錄。
- 完整分析失敗仍維持現有錯誤回報。開發診斷不混入玩家的異常標籤。
- 不修改遊戲檔案，不接管既有遊戲程序，不自動啟動遊戲驗證或下載歷史遊戲版本。
- 不宣稱有限測試涵蓋所有 demo，也不把目前遊戲的播放位置當成歷史伺服器判定。

## 執行順序

### 1. 先讓每個缺失都可重現

擴充現有 coverage，不另建日誌系統。增加穩定原因代碼，例如缺少姿勢快取、
時間戳不相符、不支援的任務、缺少資源；保留原始錯誤文字供診斷。

每種原因只擷取最多 3 個代表案例：demo tick、network tick、動畫 tick、
本機實體生命週期識別、recipe 版本、任務與所需資源。以封包序號與欄位參照
指向原始 compact 資料，不逐幀複製完整狀態。不主動收集玩家姓名或 Steam ID。

正常分析只累計數字；代表案例與重現資料採明確啟用的開發診斷模式。
報告以一份 latest 為主，初始上限 2 MiB，超出須明示截斷；原始私人錄影另存
於忽略目錄，不由診斷工具任意刪除。

驗收：

- 同一個已知失敗可由單一命令重現並得到相同原因，不必啟動 UI。
- 報告分開列出所有人物幀、實戰人物幀、骨骼／hitbox 與各規則有效樣本。
  不以混合分母或排除更多資料來提高還原率。
- 診斷啟用與停用時，規則結果相同；輸出量受限。
- 將「無符合條件的事件」「必要來源資訊缺失」「實作尚未支援」分開紀錄。

### 2. 用代表案例處理剩下的骨骼缺失

先追查快取姿勢的實際生命週期，以及各種 tick 的時鐘關係。
目前約 0.3% 是調查起點，不是已確認的來源缺口或可接受上限。

不得直接把 recipe 區域快取改為跨幀共用，也不得用最近一幀姿勢填補。
先以相鄰封包、任務依賴與遊戲對照判定快取是否應跨 recipe；只有證據支持時，
才調整狀態生命週期，並涵蓋 entity serial 變更、重生、換模型與回合重設。

驗收：每一類已觀察到的缺失都有重現、結論與回歸檢查；已修復案例不再缺失，
其餘案例具體記錄缺哪個輸入或尚未驗證哪種語義。原本成功的姿勢不可退步。

### 3. 把人工遊戲比對固定成改版檢查

將本次忽略目錄中的必要比對邏輯整理進既有 scripts；只提升可重用程式與匿名
合成測試，不提交私人 demo、真實擷取或本機路徑。

提供一個開發用分析相容性入口，串接來源檢查、離線還原、可選的遊戲擷取與
比較報告。重用現有程序隔離與擷取工具；原有啟動檢查保持獨立判定。
缺少遊戲、HLAE 或指定 fixture 時，回報「未執行」，不能記為通過。

測試案例至少涵蓋：

- v2/v3、站立／蹲下／跳躍、換槍、不同人物模型、重生與時間不連續。
- 姿勢快取讀寫、AimCS／SnapWeapon／FootIK，以及未知任務或缺少資源。
- 煙霧成形／成熟／消散、HE 擾動、穿牆、無命中與無符合條件射擊。
- 舊／新分析結果讀取、重新分析、快取重用、匯出與 UI 顯示。

基準記錄來源版本、資源指紋、解析器／規則版本、取樣範圍、時鐘對齊與既有
容許誤差。短片段未執行到的任務必須標記為未覆蓋。時鐘對齊要能獨立判定，
不能為了降低誤差任意移動樣本。

驗收：故意改壞姿勢、漏載武器或拒絕已支援格式時，檢查會失敗並指出對應類別；
恢復後通過。基準不因最新輸出而自動覆寫，不能放寬誤差掩蓋退步。

### 4. 將版本知識集中到實際能力

在既有 analysis 模組內集中處理能力判定。規則接收資料與品質資訊，不自行
檢查遊戲版號或 client 雜湊。先處理已存在的動畫與射擊設定需求，不建立通用
外掛註冊機制。

| 類型 | 判定原則 |
| --- | --- |
| 名稱、資源與字典 | 依實際引用與結構讀取；未使用的新增資源不影響分析，路徑安全檢查保留。 |
| 已知資料格式 | 檢查欄位、索引、依賴與長度；只容許已證實可忽略的尾端資料，不自動接受未知版本。 |
| 已錄製的設定 | 優先使用完整、順序正確的錄製值。缺值時只使用與來源版本相符且已驗證的預設值。 |
| 特殊動畫運算 | 格式檢查通過不等於運算相容；需有對應任務的實作證據與回歸覆蓋。 |

整個 client 的雜湊繼續作為來源識別與「需要重新檢查」的訊號。
在替代驗證完成前保留現有特殊任務保護；不能直接刪除白名單或用少數片段
通過就放行所有任務。函式層級二進位比對可作調查輔助，首階段不另做通用
反組譯／簽章比對系統。

驗收：與已用功能無關的資源新增、非必要欄位改變不讓整場失敗；真正改變的
任務、必要欄位或不明預設值會被檢查抓到。v2 舊案例與 v3 新案例皆通過。

### 5. 補齊快取、歷史來源與發布驗收

保留現有來源與版本欄位，明確檢查分析結果重用所需的解析器、資源與能力資訊。
先確認現有快取鍵已涵蓋哪些依賴，只補缺口；不為每一欄建立新快取系統。

- 舊結果可讀、可顯示；缺少新的來源證據時，不當成已通過新驗證的結果重用。
- 解析語義改變時調整 producer／schema，規則語義改變時調整 ruleset。
  純顯示修改不要求重新解析。
- 歷史資源與目前安裝資源不同須可辨識。首階段記錄來源與適配範圍，
  不自動下載舊遊戲或宣稱新版資源可精確還原所有歷史 demo。
- 回退保留原始 demo、使用者設定、影片與歷史紀錄；只重建受影響的衍生資料。
- CI 執行合成資料、既有舊版 fixture 與 UI 回歸；本機明確執行有遊戲的比對。

發布驗收包括核心測試、前端建置、桌面程式實際連結與完整 UI 驗證。
目前整套 UI 測試的既有阻擋須先排除；局部測試成功不能寫成整套通過。
曾遇到的核心增量編譯連結錯誤也說明只跑核心測試不足以驗收桌面程式。

效能與正確性分開報告。保留現有準備／分析各 30 秒的門檻；目前整場分析
約 46 秒仍不符合。正式效能比較須固定 fixture、硬體與 profile，分冷／暖快取，
不與編譯或遊戲擷取同時量測，也不以降低骨骼或煙霧覆蓋率達標。

## 本次實作與界限

`analysis_native_check --diagnose` 現在輸出受限的代表案例、穩定原因碼、
封包／實體／動畫版本與來源指紋。正常分析只累計數字。診斷顯示缺少快取
姿勢的代表案例在前一個 network tick 已寫入同一 cache ID，因此解析器改用
同一實體生命週期內的跨 recipe 姿勢狀態；實體消失、死亡、換模型／骨架、
動畫字典更新、圖定義更換、時間不連續或還原錯誤時清除。獨立遊戲擷取的
單一已驗證人物模型有 2,560 個附件位置比對點，最大誤差 0.00221 遊戲單位。

本 demo 的骨骼測量由 1,054,290／1,057,475 提升至
1,057,247／1,057,475。剩下 40 幀沒有已知的前置快取寫入，188 幀的姿勢
時間戳與封包不符；沒有以舊姿勢或插值填補。這只證實該 demo 的改善，
不能推論其他版本或人物模型皆精確。

版本政策集中於 `analysis/compatibility.rs`：一般格式仍按欄位驗證，
特殊動畫任務只在已比對的 client 版本執行；未知 client 仍可解析一般任務，
遇到特殊任務會留下明確的未驗證原因。穿煙設定只接受錄製值或已驗證的
patch 預設值。舊分析結果可顯示；重用時必須符合新的規則版本與目前遊戲
內容指紋，否則重新計算。診斷、規則有效樣本及明確接受的基準由
`scripts/check-analysis-compatibility.ps1` 串接，遊戲附件精度另由
`scripts/compare-native-attachments.mjs` 檢查。沒有可用基準時結果為
`unverified`，不是通過。

尚未取得證據的 40 個快取案例、188 個時間戳案例，以及未擷取的模型／
動畫任務仍須由將來的真實樣本驗證；這些不放寬為「已支援」。效能門檻
仍獨立於正確性評估，不以減少資料覆蓋率換取通過。本次桌面整場檢查
完成 10 名玩家與快取重用／重算一致性，但 debug 執行的首次準備
51.21 秒、分析 43.15 秒，未達各 30 秒門檻。規則中唯一
`flashed-hit-rate` 的 `noEligibleShots` 是該玩家沒有符合條件的致盲
射擊，並非解析欄位遺失；介面不將這類空項目列為異常。
